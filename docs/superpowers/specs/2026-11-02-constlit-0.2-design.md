# constlit 0.2: design

Date: 2026-11-02
Status: draft for review
Builds on: `2026-10-30-constlit-design.md` (version one, released as 0.1.0). Everything there still holds unless this document says otherwise. That includes the anti-goals, the constraints, private fields, the error style and the testing approach.

## Intent

Extend constlit beyond general-purpose literals to stable definitions from the systems people deploy on:
- Unix and Linux: file modes, signals, capabilities;
- Kubernetes: resource quantities, object names, labels;
- containers: OCI image references, digests, platforms.

The user's direction: support "generally stable definitions", without hunting for every possible one. Order: Linux first, then Kubernetes, then containers.

Why: these values are hard-coded as strings all over operators, agents, CLIs and deploy tooling. Mistakes in them fail late or, worse, silently. A memory limit of `"500m"` is half a byte. Signal 10 is SIGUSR1 on x86 and SIGBUS on macOS. An image name with uppercase letters is rejected only when a registry sees it.

## Goals

Sixteen new macros. One goes at the crate root; the rest go in four domain modules.

| module | macro | example | value |
|---|---|---|---|
| root | `mac!` | `mac!("00:1a:2b:3c:4d:5e")` | `constlit::MacAddr` |
| `unix` | `mode!` | `mode!("0755")`, `mode!("rwxr-xr-x")`, `mode!("u=rwx,go=rx")` | `constlit::unix::Mode` |
| `unix` | `signal!` | `signal!("SIGTERM")` | `constlit::unix::Signal` |
| `linux` | `cap!` | `cap!("CAP_NET_ADMIN")` | `constlit::linux::Capability` |
| `linux` | `caps!` | `caps!("CAP_NET_ADMIN, CAP_SYS_TIME")` | `constlit::linux::CapSet` |
| `k8s` | `quantity!` | `quantity!("1.5Gi")`, `quantity!("1e3")` | `constlit::k8s::Quantity` |
| `k8s` | `cpu!` | `cpu!("500m")` | `constlit::k8s::Quantity` |
| `k8s` | `mem!` | `mem!("512Mi")` | `constlit::k8s::Quantity` |
| `k8s` | `dns_label!` | `dns_label!("my-namespace")` | `&'static str` |
| `k8s` | `dns1035_label!` | `dns1035_label!("web")` | `&'static str` |
| `k8s` | `dns_subdomain!` | `dns_subdomain!("app.config.v1")` | `&'static str` |
| `k8s` | `label_key!` | `label_key!("app.kubernetes.io/name")` | `&'static str` |
| `k8s` | `label_value!` | `label_value!("web-frontend")` | `&'static str` |
| `k8s` | `selector!` | `selector!("app=web,env in (prod,staging)")` | `&'static str` |
| `oci` | `image!` | `image!("ghcr.io/org/app:1.2")` | `constlit::oci::ImageRef` |
| `oci` | `digest!` | `digest!("sha256:…")` | `constlit::oci::Digest` |
| `oci` | `platform!` | `platform!("linux/arm64/v8")` | `constlit::oci::Platform` |

Every macro works in `const` and `static` items, as before.

## Module layout (decided)

The 0.1 macros stay at the crate root because they are general-purpose. `mac!` joins them, next to `ip!` and `addr!`.

Domain macros and their types live in modules:
- `constlit::unix`: `mode!`, `signal!`, `Mode`, `Signal`. These are POSIX and are useful on macOS and the BSDs too.
- `constlit::linux`: `cap!`, `caps!`, `Capability`, `CapSet`. These are Linux-only concepts.
- `constlit::k8s`: Kubernetes.
- `constlit::oci`: containers (OCI image and distribution specs).

Why: the type names `Quantity`, `Signal`, `Mode`, `Digest` and `Platform` clash with the ecosystem types people convert to, such as k8s-openapi's `Quantity`, nix's `Signal` and oci-spec's `Platform`. Module paths also make calls say their domain: `k8s::mem!("512Mi")`.

Mechanics:
- The macros crate exports prefixed names (`k8s_mem`, `unix_mode`, ...). Each module re-exports them under short names: `pub use constlit_macros::k8s_mem as mem;`.
- Generated code uses full paths (`::constlit::k8s::Quantity`).
- The modules are always compiled. They need no new Cargo features, and the proc macro gains no dependencies.

## Non-goals (0.2)

- Run-time parsing APIs, as before.
- Docker-specific formats: port mappings (`"8080:80/tcp"`), Docker's lowercase memory units (`"512m"` meaning MiB), `"uid:gid"` user specs.
- Device numbers, errno names, interface names, sysctl names, systemd time and calendar expressions. These are candidates for later.
- Real-time signals (`SIGRTMIN+n`), because glibc fixes their numbers only at run time.
- Kubernetes field selectors, taints and tolerations, and any parsing of whole resource manifests.
- Canonicalizing quantities the way Kubernetes does (`"1.5Gi"` becoming `"1536Mi"`).
- Conversions to `oci-spec` or `nix` types. These are candidates for later.

## The macros (decided)

Error messages follow version one: the error sits on the literal, says what is wrong, and suggests a valid literal when one is obvious. The messages below are the intended wording. The builder may adjust phrasing but keeps the suggestion.

### `mac!` → `constlit::MacAddr`

- Six bytes, each exactly two hex digits, separated consistently by `:` or `-`. Hex digits may be upper or lower case.
- Errors:
  - mixed separators;
  - the Cisco dot form (`"001a.2b3c.4d5e"`), with the colon form as suggestion;
  - single-digit bytes (`"0:1a:…"`), with the zero-padded form as suggestion;
  - the wrong number of bytes, including EUI-64.
- Type: `MacAddr([u8; 6])`, private.
  - `const fn new([u8; 6])`: every byte array is a valid address, so this constructor is public and unchecked.
  - `octets()`, `is_multicast()`, `is_unicast()`, `is_local()` (locally administered), `is_universal()`.
  - `Display` writes lowercase colon form; `LowerHex`/`UpperHex` are left to the builder.
  - The usual derives, including `Ord` and `Hash`.

### `unix::mode!` → `constlit::unix::Mode`

The permission bits only (`0o7777`), never the file type.

- **Octal:** exactly 3 or 4 octal digits: `"755"`, `"0755"`, `"4755"`, `"1777"`.
  - Rust's `"0o755"` is rejected with the suggestion `"0755"`, so there is one spelling.
  - A digit `8` or `9` is an error.
- **ls form:** exactly 9 characters in `rwx` triplets, `-` for an absent bit.
  - Position 3 may be `s` (setuid plus x) or `S` (setuid without x); position 6 likewise for setgid; position 9 may be `t` or `T` for the sticky bit.
  - A leading file-type character (`"-rwxr-xr-x"`, `"drwxr-xr-x"`) is an error suggesting the 9-character form.
- **Symbolic, absolute only:** comma-separated clauses `WHO=PERMS`.
  - `WHO` is one or more of `u`, `g`, `o`, `a`; `PERMS` is zero or more of `r`, `w`, `x`, `s`, `t`.
  - Who is not mentioned gets no bits: `"u=rwx,g=rx"` is `0750`.
  - `s` is allowed only for `u`, `g` or `a`; `t` only for `o` or `a`.
  - Naming the same who twice (`"u=rwx,u=r"` or `"a=r,u=w"`) is an error.
  - Relative clauses (`+`, `-`) are an error, because they change an existing mode rather than define one: `"u+x" changes a mode; write an absolute mode like "u=rwx,go=rx" or "0755"`.
- Type: `Mode(u32)`, private, always `<= 0o7777`.
  - `bits() -> u32`, and `const fn new(u32) -> Option<Mode>`.
  - Bit queries: `is_setuid()`, `is_setgid()`, `is_sticky()`, and per-class read, write and execute queries in a shape the builder picks.
  - `Display` writes 4-digit octal (`0755`). An adaptor or method writes the 9-character ls form.
  - `From<Mode> for u32`.
  - With `std` on unix targets: `to_permissions() -> std::fs::Permissions`.

### `unix::signal!` → `constlit::unix::Signal`

- **Names:** `"SIGTERM"` or `"TERM"`, upper case.
  - Aliases are accepted and map to the same signal: `SIGIOT` = `SIGABRT`, `SIGPOLL` = `SIGIO`, `SIGCLD` = `SIGCHLD`.
  - Lower case is an error suggesting upper case.
- **Numbers are rejected,** because they differ between platforms. For numbers 1-31 the suggestion uses the generic Linux numbering: `signal numbers differ between platforms; write the name, e.g. "SIGTERM" (15 on most Linux targets)`.
- `SIGRTMIN`, `SIGRTMAX` and `SIGRTMIN+n` are errors explaining that real-time signal numbers are only known at run time.
- **Target-dependent numbers.** The proc macro does not know the target, so it emits the signal by name: a path to a per-target constant in the runtime crate, or `#[cfg]`-gated tokens. The user's crate resolves it for its own target. The builder picks the mechanism; the behavior is fixed:
  - **Linux and Android, generic numbering:** x86, x86_64, arm, aarch64, riscv, powerpc, s390x, loongarch.
  - **Linux, mips** numbering.
  - **Linux, sparc** numbering.
  - **BSD numbering:** macOS, iOS, FreeBSD, NetBSD, OpenBSD, DragonFly. Where these differ, the gap is in signals above 31 (FreeBSD's `SIGTHR`/`SIGLIBRT`), which are out of scope.
  - A signal the target lacks (for example `SIGPWR` or `SIGSTKFLT` on macOS, or `SIGINFO` on Linux) is a compile error in the user's crate that names the signal and the target family.
  - Any other target (Windows, wasm and so on) is a compile error saying signals are unix-only.
  - Signals in scope: the 1-31 range on Linux plus `SIGEMT`, `SIGINFO` and `SIGLOST` where the target has them.
- Type: `Signal(i32)`, private.
  - `number() -> i32` (const), and `name() -> &'static str` (canonical `SIG…` name; const).
  - `Display` writes the name.
  - `Eq`, `Ord`, `Hash` are by number.

### `linux::cap!` → `constlit::linux::Capability`

- **Names:** `"CAP_NET_ADMIN"` or `"NET_ADMIN"` (the Docker and Kubernetes spelling), upper case.
  - Lower case (libcap's `cap_net_admin`) is an error suggesting upper case.
  - `"ALL"` is an error, because the set of all capabilities depends on the kernel.
  - An unknown name gets a "did you mean" suggestion when one is close.
- Known capabilities are numbers 0-40, `CAP_CHOWN` through `CAP_CHECKPOINT_RESTORE`. This is stable kernel ABI, and new kernel capabilities can be added in later releases.
- Type: `Capability(u8)`, private.
  - `number() -> u8`, and `name() -> &'static str` (canonical `CAP_…`).
  - `Display` writes the name.
  - `Capability::from_number(u8) -> Option<Self>` for run time.

### `linux::caps!` → `constlit::linux::CapSet`

- A comma-separated list of names as in `cap!`. Spaces after the commas are optional.
- Errors:
  - a duplicate name;
  - an empty literal, suggesting `CapSet::EMPTY`;
  - a trailing comma.
- Type: `CapSet(u64)`, a bitmask by capability number.
  - `EMPTY`, `bits() -> u64`.
  - `contains(Capability)`, `with(Capability)`, `union`, `intersection`, `difference`, `len()`, `is_empty()`, all const.
  - An iterator over the capabilities.
  - `Display` writes a comma-separated list of names in number order.

### `k8s::quantity!`, `cpu!`, `mem!` → `constlit::k8s::Quantity`

**Grammar** (Kubernetes' `resource.Quantity`):

```
quantity  ::= [sign] number suffix
number    ::= digits | digits "." digits | digits "." | "." digits
suffix    ::= binarySI | decimalSI | ("e" | "E") [sign] digits
binarySI  ::= Ki | Mi | Gi | Ti | Pi | Ei
decimalSI ::= n | u | m | "" | k | M | G | T | P | E
```

Here `E` alone is exa, and `E` followed by digits is an exponent, exactly as in Kubernetes.

**Strictness** (where Kubernetes would silently round or cap, we reject):
- Finer than milli (more than 3 decimal places after the suffix is applied, such as `"0.1m"` or `"100n"`) is an error. Kubernetes rounds these up.
- A magnitude above 2^63-1 units is an error. Kubernetes caps it.
- Whitespace anywhere is an error. A suffix with the wrong case (`"Mi"` vs `"mi"`, `"Ki"` vs `"KI"`) is an error with a suggestion. `"K"` suggests `"k"` (1000) or `"Ki"` (1024).

**`quantity!`** accepts everything the grammar allows within the rules above, including negative values.

**`cpu!`** adds rules for CPU amounts:
- no negative values;
- no binary suffixes (`"2Gi"` is an error saying CPU is counted in cores; write e.g. `"2"` or `"2000m"`);
- a non-zero value below `1m` is already rejected by the milli rule.

**`mem!`** is for memory, storage and anything else counted in bytes:
- no negative values;
- the value must be a whole number of bytes. The headline error is: `"500m" is 0.5 bytes ("m" means milli); did you mean "500Mi" or "500M"?` More generally, any fraction of a byte is an error with the nearest whole-number spelling as suggestion.

**Type:** `Quantity { millis: i128, text: &'static str }`, private.
- `millis() -> i128`.
- `value() -> i64`, rounded up to a whole unit, matching Kubernetes' `Value()`.
- `as_str() -> &'static str` returns the literal as written.
- `Display` writes the literal as written, which Kubernetes accepts unchanged.
- `Eq`, `Ord` and `Hash` compare the value only, so `quantity!("1Ki") == quantity!("1024")`.
- With the new `k8s-openapi` feature: `From<Quantity> for k8s_openapi::apimachinery::pkg::api::resource::Quantity`.
  - That type wraps a `String`, so the feature needs `alloc`. The builder decides between an `alloc` feature and `std`.
  - k8s-openapi requires the final binary to pick a Kubernetes version feature. Library crates must not pick one, so constlit's dependency enables none. The tests pick one through a dev-dependency.
  - docs.rs and a bare `cargo check --features k8s-openapi` have no version feature either. The builder makes both work, for example with `K8S_OPENAPI_ENABLED_VERSION` in the docs.rs metadata and in CI.

### `k8s` names and labels → `&'static str`

These macros validate their literal and expand to it unchanged.

- **`dns_label!`** (RFC 1123 label: namespaces, most object names):
  - 1-63 characters of `a-z`, `0-9` and `-`;
  - starts and ends with an alphanumeric character.
- **`dns1035_label!`** (RFC 1035 label: Service names): the same, but it must start with a letter.
- **`dns_subdomain!`** (RFC 1123 subdomain: ConfigMaps, Secrets, CRDs and others):
  - at most 253 characters;
  - dot-separated RFC 1123 labels.
- **`label_key!`:** `[prefix "/"] name`.
  - The prefix is a DNS subdomain.
  - The name is 1-63 characters of `A-Z a-z 0-9 - _ .`, starting and ending with an alphanumeric character.
- **`label_value!`:** empty, or a name as in `label_key!` (at most 63 characters).
- **`selector!`:** Kubernetes' label-selector syntax.
  - Comma-separated requirements: `key`, `!key`, `key=value`, `key==value`, `key!=value`, `key in (v1,v2)`, `key notin (v1,v2)`, `key > 5` and `key < 5` (integer values).
  - Keys and values are checked as in `label_key!` and `label_value!`.
  - Whitespace around operators and values is allowed, as Kubernetes allows it.
  - An empty selector is an error. In Kubernetes an empty selector matches everything, which deserves to be written out on purpose. The error suggests using the API's "match everything" form instead (for example `LabelSelector::default()`).
- **Errors:**
  - Upper case in a DNS name: `names must be lower case; write "my-app"`.
  - Too long: says the limit and the length.
  - Bad first or last character, or a bad character in the middle.
  - Each names the offending part of a label key, the prefix or the name.

### `oci::image!` → `constlit::oci::ImageRef`

**Grammar:** the distribution reference grammar (`distribution/reference`):

```
reference        ::= name [":" tag] ["@" digest]
name             ::= [domain "/"] path
domain           ::= host [":" port]
path             ::= component ("/" component)*
component        ::= [a-z0-9]+ (separator [a-z0-9]+)*
separator        ::= "." | "_" | "__" | "-"+
tag              ::= [A-Za-z0-9_][A-Za-z0-9_.-]{0,127}
```

- **The domain is recognized as in Docker:** the first path component is a registry when it contains `.` or `:`, or is `localhost`. Otherwise the registry is `docker.io`. A single-component name on Docker Hub gets the `library/` prefix.
- **Limits:** the name is at most 255 characters. The digest follows `digest!` below.
- **Errors:**
  - Upper case in the repository: `repository names must be lower case; write "org/app"`.
  - A tag longer than 128 characters.
  - A malformed digest, which uses `digest!`'s messages.
  - A scheme (`"https://ghcr.io/…"`), suggesting the reference without it.
  - Whitespace.
- **Type:** `ImageRef`, private. It holds `&'static str` parts computed at compile time plus `Option<Digest>`.
  - `registry()`: `"docker.io"` when omitted; otherwise as written.
  - `repository()`: normalized, including `library/`.
  - `tag() -> Option<&'static str>`.
  - `digest() -> Option<Digest>`.
  - `as_str()` returns the literal as written.
  - `canonical() -> &'static str`: the fully qualified form, `"docker.io/library/nginx:latest"`.
    - `latest` is added only when there is no tag and no digest, matching Docker.
    - It is computed by the proc macro, so it costs nothing at run time.
  - `Display` writes the literal as written.
  - `Eq` and `Hash` compare `canonical()`.

### `oci::digest!` → `constlit::oci::Digest`

- `"sha256:"` plus 64 lowercase hex digits, or `"sha512:"` plus 128. These are the algorithms registered in the OCI image spec.
- Errors:
  - upper-case hex (OCI requires lower case), suggesting the lowercase literal;
  - a wrong length, saying the expected length;
  - an unknown algorithm, listing the two supported ones;
  - a missing algorithm (bare hex), suggesting `"sha256:…"` when the length is 64.
- Type: an enum-like private type holding `[u8; 32]` or `[u8; 64]`, with the bytes decoded at compile time.
  - `algorithm() -> DigestAlgorithm` (`Sha256` | `Sha512`), and `as_bytes() -> &[u8]`.
  - `Display` writes `"sha256:<hex>"`.
  - The usual derives.

### `oci::platform!` → `constlit::oci::Platform`

- `"os/arch"` or `"os/arch/variant"`, using Go's `GOOS` and `GOARCH` names as OCI does.
- **Known values** (checked; others are errors):
  - os: `aix`, `android`, `darwin`, `dragonfly`, `freebsd`, `illumos`, `ios`, `js`, `linux`, `netbsd`, `openbsd`, `plan9`, `solaris`, `wasip1`, `windows`.
  - arch: `386`, `amd64`, `arm`, `arm64`, `loong64`, `mips`, `mipsle`, `mips64`, `mips64le`, `ppc64`, `ppc64le`, `riscv64`, `s390x`, `wasm`.
  - variant: for `arm`, `v5`-`v8`; for `arm64`, `v8`, `v8.1`-`v8.9`, `v9`, `v9.1`-`v9.5`; for `amd64`, `v1`-`v4`. Other architectures take no variant.
  - The os and arch are checked separately, not as pairs.
- **Suggestions for common non-Go names:**
  - `x86_64` / `x86-64` → `amd64`;
  - `aarch64` → `arm64`;
  - `armv7` / `armhf` → `arm/v7`;
  - `i386` / `i686` / `x86` → `386`;
  - `macos` / `osx` → `darwin`.
- Upper case is an error suggesting lower case.
- Type: `Platform`, private, with `os()`, `arch()`, `variant() -> Option<&'static str>`.
  - `Display` writes `os/arch[/variant]` as written.
  - Equality is as written. Docker treats `linux/arm64` and `linux/arm64/v8` as the same, but we do not normalize (documented).

## Constraints

As in version one, with these additions:
- No new dependencies in either crate by default. The proc macro stays on `proc-macro2`, `quote` and `litrs` (plus jiff under `tz`).
- New optional feature: `k8s-openapi`, needing `alloc` or `std` (builder's choice; see above).
- `Mode::to_permissions` sits under `std` and `cfg(unix)`.
- MSRV stays 1.88.

## Testing

As in version one:
- parser unit tables with exact messages;
- trybuild UI snapshots;
- `const` tests;
- `no_std` build;
- random tests with SplitMix64;
- oracles where an established implementation exists.

The oracles:
- **`signal!`:** a static assertion that each signal's number equals the `libc` crate's constant for the same target. It runs on the host, and on a few foreign targets with `cargo check --tests --target …` (e.g. `aarch64-apple-darwin`, `mips64-unknown-linux-gnuabi64` if its std is available, `sparc64-unknown-linux-gnu`). The builder picks the targets that `rustup` can provide.
- **`cap!`:** the `caps` crate, or the `libc`/`linux-raw-sys` constants (builder's choice), for every name and number.
- **`quantity!`:** a Kubernetes quantity parser such as `kube_quantity`, on random literals in the accepted range. Where it disagrees with the Go behavior, Go wins and the test documents the case. The builder also hand-checks a table of values against Kubernetes' own `quantity_test.go` cases.
- **`image!`:**
  - an established reference parser (e.g. `oci-spec`'s distribution `Reference` or `oci-client`'s `Reference`; builder verifies) on random well-formed and malformed references;
  - a table taken from `distribution/reference`'s `reference_test.go` and `normalize_test.go`.
- **`mac!`:** a hand-written round trip (`Display` then parse) over random bytes; no external oracle.
- **The names, `selector!` and `platform!`:** tables of valid and invalid inputs. The selector table is taken from Kubernetes' `selector_test.go` where practical.

## Calls I made (for review)

- Accepting both spellings where tools differ but meaning doesn't: `SIGTERM`/`TERM`, `CAP_X`/`X`, and `:`/`-` in MAC addresses.
- Rejecting `"0o755"`, lowercase signal and capability names, `"ALL"`, the empty selector, and upper-case digest hex.
- Rejecting quantities Kubernetes would silently round or cap.
- Keeping `"1E3"` (exponent) valid as Kubernetes does, even though it reads close to `"1E"` (exa).
- `Quantity`, `ImageRef` and `Platform` display the literal as written, not a canonical form; `ImageRef::canonical()` gives the fully qualified form.
- Names and labels return `&'static str` rather than newtypes, for interop and zero cost.
- `Platform` checks the os and arch separately, not as pairs, and does not normalize default variants.
- `MacAddr::new` is public and unchecked, since every 6-byte array is valid.

## Left to the builder

- How `signal!` resolves numbers per target (const paths or `cfg`-gated tokens), as long as the behavior above holds.
- Exact method sets beyond those named, and the shape of the mode bit queries.
- `alloc` versus `std` for the `k8s-openapi` feature.
- Which oracle crate versions to pin, and which foreign targets the signal check covers.
