# constlit 0.3: design

Date: 2026-11-02
Status: decided by the builder. The user asked for these three phases to be planned, run and merged without check-ins; every call below is the builder's and is listed for review at release time.
Builds on: `2026-10-30-constlit-design.md` and `2026-11-02-constlit-0.2-design.md`. All their rules still hold:
- the anti-goals (no silent ambiguity, no run-time cost, no heavy default dependencies, no unhelpful errors);
- private fields with `const fn` accessors;
- errors on the literal that suggest a valid literal;
- `no_std`, MSRV 1.88;
- oracles wherever an authoritative implementation exists, and every suggestion re-parsed by the tests.

## Intent

0.3 adds three things, built in the user's order with no release in between:
1. the Docker and Linux values that 0.2 left out;
2. Cargo version requirements;
3. a `systemd` module.

The user picked these from the builder's list after 0.2.0.

## Phase 7: Docker and Linux values

| macro | example | value |
|---|---|---|
| `docker::port!` | `port!("8080:80")`, `port!("127.0.0.1:8080:80/tcp")`, `port!("8000-8010:8000-8010/udp")` | `constlit::docker::PortMapping` |
| `linux::errno!` | `errno!("ENOENT")` | `constlit::linux::Errno`, numbered for the build target |
| `linux::ifname!` | `ifname!("eth0")` | `&'static str` |
| `linux::dev!` | `dev!("8:0")` | `constlit::linux::DevNum` |

### `docker::port!`

- This goes in a new module, `constlit::docker`. Port publishing is part of the Docker CLI and Compose, not the OCI specs.
- **Grammar:** the `docker run -p` form, `[host_ip:][host_port:]container_port[/protocol]`.
  - Each port may be a range `a-b`.
  - `host_port` may be empty (`"127.0.0.1::80"`).
  - An IPv6 `host_ip` is bracketed (`"[::1]:8080:80"`).
  - The protocol is `tcp`, `udp` or `sctp`, lower case; it defaults to `tcp`.
- **Oracle:** `github.com/docker/go-connections/nat.ParsePortSpec` (v0.8.2). It decides every case this text leaves open, such as port 0 and unequal range lengths, and the plan records the cases it decided.
- **Type:** `PortMapping`.
  - Private fields: `host_ip: Option<core::net::IpAddr>`, `host: Option<PortRange>`, `container: PortRange`, `protocol: Protocol`.
  - `PortRange { start: u16, end: u16 }`; `Protocol::{Tcp, Udp, Sctp}`.
  - `Display` writes a canonical form: the host IP if any, the host ports if any, the container ports, and `/protocol` always.
  - Equality uses the fields.
- **Strictness:**
  - an upper-case protocol is an error suggesting lower case;
  - a range whose end is below its start is an error;
  - anything the oracle rejects is an error.

### `linux::errno!`

- Names only, with the `E`: `"ENOENT"`.
  - Numbers are errors, because they differ between architectures.
  - Lower case is an error suggesting upper case.
  - The aliases `EWOULDBLOCK` (= `EAGAIN`), `ENOTSUP` (= `EOPNOTSUPP`) and `EDEADLOCK` are accepted. `EDEADLOCK` equals `EDEADLK` everywhere except powerpc, mips and sparc, where it has its own number.
- Numbers come from per-target tables in the runtime crate, chosen by `cfg` in the user's crate, as `unix::signal!` does.
  - The families are Linux generic, powerpc, mips and sparc.
  - Android uses the generic numbering.
  - Any other target is a compile error. It lives in `linux` because the tables are Linux's; the BSDs number errno differently above 34.
- The tables are generated from the `libc` crate's source (0.2.191). They are checked with static assertions against `libc` on the host, and with `cargo check` on aarch64, sparc64 and powerpc64le.
- **Type:** `Errno(i32)`, with `number()`, `name()` (canonical), `from_number`, and `Display` writing the name.

### `linux::ifname!`

- The kernel's `dev_valid_name` rule:
  - 1-15 bytes;
  - not `.` or `..`;
  - no `/`, `:` or whitespace.
- **Stricter than the kernel:** only printable ASCII is allowed, and `%`, the kernel's name-template marker (`eth%d`), is an error. This is what systemd's network tools accept for real names.
- Expands to `&'static str`.

### `linux::dev!`

- `"major:minor"` in decimal: major 0-4095 and minor 0-1048575, the kernel's `MKDEV` limits.
- **Type:** `DevNum`, with `major()`, `minor()`, and `to_dev_t() -> u64` using glibc's `makedev` encoding. The oracle is `libc::makedev` on the host.

## Phase 8: `version_req!`

- `version_req!(">=1.2, <2")` gives `constlit::VersionReq`, at the crate root next to `version!`.
- **Syntax:** Cargo's, as the `semver` crate parses it. npm's syntax is not supported.
  - Every form `semver::VersionReq::parse` accepts is accepted: `^`, `~`, `=`, `>`, `>=`, `<`, `<=`, `*` and `x` wildcards, bare versions (caret), and comma-separated comparators. Amended during Phase 8: build metadata, which semver silently ignores, is an error.
  - A bare `"1.2"` means `^1.2`, as in Cargo.toml. It is not ambiguous here, because the syntax is fixed as Cargo's.
- **Type:**
  - `VersionReq` holds `&'static [Comparator]` built at compile time, plus the literal as written.
  - `Comparator` has `op`, `major`, `minor: Option<u64>`, `patch: Option<u64>` and `pre: &'static str`.
  - `matches(&Version) -> bool` follows the `semver` crate's semantics, including its pre-release rule.
  - `Display` writes the literal.
  - `to_semver()` is available under the `semver` feature.
- **Oracles:** `semver::VersionReq::parse` for parsing, and `semver::VersionReq::matches` on random versions for matching.

## Phase 9: the `systemd` module

| macro | example | value |
|---|---|---|
| `systemd::timespan!` | `timespan!("5min 30s")`, `timespan!("1.5h")` | `core::time::Duration` |
| `systemd::calendar!` | `calendar!("Mon..Fri *-*-* 09:00")`, `calendar!("daily")` | `constlit::systemd::CalendarSpec` |
| `systemd::unit!` | `unit!("nginx.service")`, `unit!("getty@tty1.service")` | `&'static str` |

The oracle for time spans and calendars is `systemd-analyze` (systemd 262 here):
- `systemd-analyze timespan` gives a span in µs.
- `systemd-analyze calendar --iterations=N --base-time=…` gives the normalized form and the next elapse times. It runs with `TZ` set to fixed zones, including a DST zone.

### `systemd::timespan!`

- systemd's units:
  - `usec`/`us`/`µs`;
  - `msec`/`ms`;
  - `seconds`/`second`/`sec`/`s`;
  - `minutes`/`minute`/`min`/`m`;
  - `hours`/`hour`/`hr`/`h`;
  - `days`/`day`/`d`;
  - `weeks`/`week`/`w`;
  - `months`/`month`/`M` (30.44 days);
  - `years`/`year`/`y` (365.25 days).
- Decimals and whitespace are allowed as systemd allows them.
- **Strictness:**
  - A bare number (systemd's default unit depends on the setting) is an error suggesting `"30s"`.
  - `M` is an error asking `"month"` or `"min"`, because it reads like `m`.
  - `infinity` is an error, because `Duration` has no infinity.
  - A value finer than 1 µs, which systemd can't represent, is an error.

### `systemd::calendar!`

- systemd's calendar grammar:
  - optional weekdays (names, ranges `..`, lists);
  - an optional date `year-month-day` with `*`, lists, ranges, repetitions (`/n`) and `~` (from the end of the month);
  - an optional time `hour:minute[:second]` with the same forms;
  - the shorthands `minutely`, `hourly`, `daily`, `weekly`, `monthly`, `yearly`/`annually`, `quarterly` and `semiannually`.
- **Narrowed (builder's call):**
  - The only timezone suffix allowed is `UTC`; an IANA zone name is an error naming the limit.
  - Fractional seconds are errors.
  - Both keep the run-time side small and `no_std`.
  - Amended during Phase 9: lists after `~` are errors (systemd's acceptance there is irregular); one day, a range, or one open step (`~07/1`) is supported.
- **Type:** `CalendarSpec`.
  - Its fields are compile-time bit sets, plus the `~` and UTC flags.
  - `Display` writes systemd's normalized form exactly; the oracle checks it.
  - With the `jiff` or `chrono` feature, `next_after` returns the next elapse after a zoned date-time, in that zone (or in UTC for a `UTC` spec), matching `systemd-analyze calendar` with the same base time and `TZ`. That includes the behaviour around DST changes, which the plan pins from the oracle.
- `CalendarSpec::matches` takes a civil date and time without a zone.

### `systemd::unit!`

- systemd's `unit_name_is_valid` rules:
  - `prefix[@instance].type`, where `type` is one of `service`, `socket`, `device`, `mount`, `automount`, `swap`, `target`, `path`, `timer`, `slice` or `scope`;
  - a template `prefix@.type` is valid;
  - characters `[A-Za-z0-9:_.\-]` in the prefix and the instance, plus `\` (escapes) in the instance;
  - at most 255 characters.
- An unknown type is an error with "did you mean" (for example `.servcie`).
- Expands to `&'static str`.
- The oracle is a table built from systemd's `test-unit-name.c` cases.
