**Goal:** Add the `k8s` module: `quantity!`, `cpu!` and `mem!` (all producing `constlit::k8s::Quantity`), the name and label macros (`dns_label!`, `dns1035_label!`, `dns_subdomain!`, `label_key!`, `label_value!`), `selector!`, and the `k8s-openapi` conversion.

**Architecture:** This follows phase 4.
- `constlit-macros` gets three parser modules: `quantity.rs`, `k8s_names.rs` and `selector.rs`. Each is a set of pure functions over `&str`, and expansion goes through `input::expand`. The proc macros are exported as `k8s_quantity`, `k8s_cpu`, and so on.
- `constlit/src/k8s/` re-exports them under short names, as `unix` and `linux` do.
- The name, label and selector macros validate their literal and expand to the literal itself (`&'static str`).
- The oracle is Kubernetes itself. A small Go program in `constlit-macros/oracle/` runs `k8s.io/apimachinery` over generated inputs and writes TSV fixtures. The Rust tests compare against those fixtures, so `cargo test` needs no Go.

## Decisions this plan makes (my calls, within the spec)

- **The oracle is the Go implementation, not `kube_quantity`.**
  - The spec names `kube_quantity` as an example and says Go wins where the two disagree.
  - While writing the plan I found that `kube_quantity` 0.9 parses numbers through `f64`, so it can't serve as an exact oracle.
  - The Go program (`constlit-macros/oracle/main.go`) calls:
    - `resource.ParseQuantity`, plus `AsDec()` and `Value()` on the result;
    - `validation.IsDNS1123Label`, `IsDNS1035Label`, `IsDNS1123Subdomain`, `IsQualifiedName` and `IsValidLabelValue`;
    - `labels.Parse`.
  - It writes the fixtures under `constlit-macros/src/testdata/`. Those files and `oracle/` are listed in `exclude` in `constlit-macros/Cargo.toml`, so they don't ship.
- **Fixture format.** Each fixture is a TSV file.
  - Lines starting with `#` are comments; the first one names the apimachinery version.
  - The generator never puts a tab or newline in an input.
  - Quantity lines are `input<TAB>ok<TAB><AsDec string><TAB><Value()>` or `input<TAB>err`.
  - Name lines are `kind<TAB>input<TAB>ok|err`, where kind is one of `dns_label`, `dns1035_label`, `dns_subdomain`, `label_key` or `label_value`.
  - Selector lines are `input<TAB>ok|err`.
- **How the oracle agrees with our strictness.**
  - **Anything we accept, Go accepts.** For a quantity, Go's exact decimal × 1000 must also equal our millis.
  - **Anything Go accepts, we accept, with listed exceptions.** Where we reject it, our message must belong to that macro's strictness list, and the test checks that the input really is in that class:
    - quantity: finer than milli, or out of range (judged on Go's decimal);
    - selector: empty selector, or an empty value in a set;
    - all macros: leading or trailing whitespace.
- **`mem!` rejects the `n`, `u` and `m` suffixes outright.** This applies even when the value happens to be a whole number of bytes: `mem!("2000m")` is 2 bytes, and the writer almost surely meant `2000Mi`. That is the anti-goal's "could mean two things" case.
- **`Quantity::value()` rounds away from zero,** as Kubernetes' `Value()` does: `-1.5` becomes `-2` and `0.5` becomes `1`. The Go fixture's `Value()` column pins this.
- **The suggestion for a too-fine quantity** rounds the magnitude up to the next milli and keeps the sign: `"0.1m"` suggests `"1m"`, and `"-0.1m"` suggests `"-1m"`.
- **Empty values in a selector set are rejected.** `(a,)`, `(,a)` and `(a,,b)` are errors, although Kubernetes reads each empty slot as the value `""`. A trailing comma there is far more likely a typo than an intent.
- **Subdomain parts have no 63-character limit.** Go's `IsDNS1123Subdomain` checks only the pattern and the 253-character total. The spec's "dot-separated RFC 1123 labels" is read as the pattern, and the fixture pins it.
- **docs.rs and `--all-features`.** A hidden feature `__k8s-openapi-latest = ["k8s-openapi/latest"]` lets those builds pick a Kubernetes version. This is the pattern k8s-openapi documents for library crates (`kube_quantity` uses `__check`). It is marked "internal: never enable" in `Cargo.toml`.

## Review Focus

1. **Exponent versus exa.**
   - `"1E"` is 10^18 (exa). `"1E3"` and `"1E+3"` are 1000. `"1e-3"` is `1m`. `"1Ei"` is 2^60.
   - A reasonable person expects exactly Kubernetes' reading.
   - Pinned by `quantity_values` (Task 1) and the Go fixture.
2. **Rounding in `value()` for negatives and halves.** `quantity!("-1.5").value() == -2` and `quantity!("0.5").value() == 1`. Pinned by `quantity_accessors` (Task 1) and the fixture's `Value()` column.
3. **Long but exact literals must not overflow.**
   - These parse exactly: `"0000000000000000000000000001"` (1), `"1.000000000000000000000000000000"` (1), and `"1000000000000000000000000n"` (10^15).
   - `"9223372036854775807"` is accepted and `"9223372036854775808"` is out of range.
   - Pinned by `quantity_values` and `quantity_errors` (Task 1).
4. **Equal values from different spellings.** `quantity!("1Ki") == quantity!("1024")`, with equal hashes, while `Display` keeps each literal as written. Pinned by `quantity_accessors` (Task 1).
5. **Case rules differ by kind.**
   - Label values and label-key names may be upper case (`"Web"`, `"App.Kubernetes"` as a name part).
   - DNS names and label-key prefixes may not.
   - Pinned by `name_values` (Task 2) and the fixture.

  - `Display` writes `text`.
- `quantity!`, `cpu!` and `mem!` expand to `::constlit::k8s::Quantity::__new_unchecked(<millis>i128, "<literal>")`.

**The exact value (algorithm the tests don't determine):**
1. Turn the number into an integer significand `S` (digits with the point removed and leading zeros dropped) and a decimal exponent `E`. `E` is minus the number of fraction digits, plus the suffix's power of ten (`n` −9, `u` −6, `m` −3, `k` 3, … `E` 18, or the exponent's value). Binary suffixes contribute a factor `2^(10·k)`.
2. Move trailing zeros of `S` into `E`, so every check works on a short `S`.
3. `millis = S · 2^(10k) · 10^(E+3)`.
   - If `E + 3 < 0`, the division by `10^-(E+3)` must be exact; otherwise the value is finer than milli.
   - Every multiplication is checked. Once a running magnitude passes `(2^63 − 1) · 1000`, the result is out of range, even before overflow.
   - An exponent whose absolute value is above 100 decides itself: zero if `S` is 0, otherwise out of range (exponent > 0) or finer than milli (exponent < 0).

**Interfaces:**
- Consumes `k8s_names::check_label_key` and `check_label_value` (Task 2).
- Produces `constlit_macros::selector::check_selector(s: &str) -> Result<(), String>`. `selector!` expands to the literal (`&'static str`).

**Grammar** (Kubernetes' `labels.Parse`):
- Tokens are separated by optional whitespace: spaces, tabs, `\r` and `\n`.
- An identifier is a run of characters other than whitespace and `! = > < ( ) ,`. The identifiers `in` and `notin` are keywords.
- Requirements are separated by `,`. Each requirement is one of:
  - `KEY` (exists);
  - `!KEY` (does not exist);
  - `KEY (= | == | !=) VALUE`, where VALUE may be empty, as in `key=`;
  - `KEY (in | notin) ( VALUE {, VALUE} )`;
  - `KEY (> | <) INTEGER`, where the integer is a signed i64.
- Keys are checked with `check_label_key`, and values (other than integers) with `check_label_value`.
- The fixture is the authority on anything this summary leaves open.

**Error messages (exact):**

| input | message |
|---|---|
| `""` | `an empty selector matches everything; use your API's match-all form instead, e.g. LabelSelector::default()` |
| `" app=web"` | `remove the spaces around the literal` |
| `"app=web,"` | `remove the trailing ","` |
| `"app=web,,tier=db"`, `",app=web"` | `empty requirement between commas` |
| `"App@=web"` | ``key "App@": invalid character `@` in the name part; use letters, digits, "-", "_" and "."`` (any `check_label_key` message, prefixed with `key "<key>": `) |
| `"app=web app"` | `expected "," or the end after "app=web", found "app"` |
| `"app=-web"` | `value "-web": label values must start and end with a letter or digit` |
| `"app in (a,)"`, `"app in (,a)"`, `"app in (a,,b)"` | `empty value in "(a,)"; remove the extra ","` (the set as written) |
| `"app in ()"` | `"in" needs at least one value` (`"notin"` likewise) |
| `"app in (a"` | `missing ")"` |
| `"app in a"` | `expected "(" after "in"` |
| `"app > x"` | `"x" after ">" must be a whole number` |
| `"!app=web"` | `"!" checks that a key is absent; write "!app" or "app!=web"` |
| `"app=="` | allowed: the empty value |
| `"=web"` | `missing key before "="` |
| `"app (a)"` | `expected an operator or "," after "app", found "("` |
