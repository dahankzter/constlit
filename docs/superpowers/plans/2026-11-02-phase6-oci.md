# constlit Phase 6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `oci` module: `digest!`, `image!` and `platform!`, producing `constlit::oci::Digest`, `ImageRef` and `Platform`.

**Architecture:** This follows phase 5.
- `constlit-macros` gets three parser modules: `oci_digest.rs`, `oci_image.rs` and `oci_platform.rs`. The proc macros `oci_digest`, `oci_image` and `oci_platform` are re-exported from `constlit/src/oci/mod.rs` under short names.
- Everything is decided at compile time, and the runtime types only hold the results. A digest's bytes are decoded by the macro. An image reference's normalized parts and its canonical string are computed by the macro and stored as `&'static str`.
- The oracle is again the Go code these formats come from. `constlit-macros/oracle/main.go` gains three subcommands:
  - `digest` uses `github.com/opencontainers/go-digest`;
  - `image` uses `github.com/distribution/reference`;
  - `platform` uses `github.com/containerd/platforms` and `go tool dist list`.

  Each writes a TSV fixture to `constlit-macros/src/testdata/`.

**Tech Stack:**
- As in phase 5.
- No new Rust dependencies.
- New Go dependencies of the oracle only, at the versions checked while writing this plan: `github.com/opencontainers/go-digest` v1.0.0, `github.com/distribution/reference` v0.6.0 and `github.com/containerd/platforms` v0.2.1.

**Spec:** `docs/superpowers/specs/2026-11-02-constlit-0.2-design.md`. Relevant sections: `oci::image!`, `oci::digest!`, `oci::platform!`, Module layout, Testing.

## Global Constraints

- Every earlier constraint still holds:
  - stable Rust ≥ 1.88, edition 2024;
  - `constlit` is `#![no_std]` with no allocation;
  - no `unsafe`;
  - every error is a `compile_error!` on the literal, naming the problem and the nearest valid literal where one exists;
  - no silent ambiguity;
  - every macro works in `const` and `static` items;
  - leading or trailing whitespace is the error `remove the spaces around the literal`.
- Own types have private fields, `const fn` accessors and `#[doc(hidden)]` constructors for the macros. Generated code uses only `::constlit::…` and `::core::…` paths.
- The `oci` module is always compiled. There are no new features.
- Oracle tests follow phase 5's rules:
  - **Anything we accept, Go accepts,** and the normalized parts match.
  - **Where Go accepts and we reject,** our message must belong to the strictness list of the macro concerned, checked against the input.
  - **Coverage:** the test requires a minimum number of compared lines and of Go-accepted lines.
- Checks at the end of every task: the phase 5 list (tests with all features and with defaults, macros tests with and without `tz`, the five clippy runs, thumbv7m, `+1.88`, fmt), plus `cargo doc -p constlit --all-features --no-deps` with no warnings.
- Regenerating a fixture must reproduce the existing ones byte for byte. Check this with `go run . <sub> | cmp - ../src/testdata/<file>` for each older subcommand.

## Decisions this plan makes (my calls, within the spec)

- **Normalized parts, from Go's `ParseNormalizedNamed`.**
  - `ImageRef::registry()` and `repository()` return the parts `distribution/reference` normalizes to.
  - An omitted registry, and `index.docker.io`, become `docker.io`. A Docker Hub name with no `/` gets `library/`.
  - The spec says "otherwise as written" for the registry. The only difference is `index.docker.io`, which Go canonicalizes, so `canonical()` and `registry()` agree.
  - `as_str()` and `Display` keep the literal as written.
- **An upper-case first component without `.` or `:` is an error.** Docker reads `"MyOrg/app"` as a registry host named `MyOrg`, which a reasonable person almost never means. The error says so and suggests `"myorg/app"`. An upper-case registry that is clearly a host, like `"Registry.Example.com/app"`, stays valid, as in Go.
- **Digests: sha256 and sha512 only,** as the spec says. go-digest also accepts `sha384`. Our rejection is a strictness class in the oracle, for both `digest!` and digests inside `image!`.
- **The 255-character limit applies to the repository path,** as in `distribution/reference` (`RepositoryNameTotalLengthMax` applies to the path). The spec says "the name"; Go is the authority.
- **`Platform` stores `os`, `arch` and `variant` only.** `Display` writes them joined with `/`, which is the literal, because only exact known spellings are accepted.
- **Platform aliases are checked against containerd.** Each alias suggestion (`x86_64` → `amd64` and so on) must equal what containerd's `platforms.Normalize` produces for the same input. That makes containerd the oracle for the suggestions, while we stay strict about what we accept.

## Review Focus

1. **Docker Hub normalization.**
   - `"nginx"` → `docker.io/library/nginx:latest`.
   - `"user/app"` → `docker.io/user/app:latest` (no `library/`).
   - `"docker.io/nginx"` and `"index.docker.io/nginx"` → `docker.io/library/nginx:latest`.
   - `"localhost/app"` and `"localhost:5000/app"` keep `localhost` (with its port) as the registry.

   Pinned by `image_values` (Task 2) and the fixture.
2. **Tag versus port.**
   - `"registry.example.com:5000/app"` has a port and no tag.
   - `"app:5000"` has the tag `5000`.
   - `"registry:5000/app:1.2"` has both.

   Pinned by `image_values` (Task 2).
3. **Digest-only references get no `latest`.** `"nginx@sha256:<64 hex>"` canonicalizes to `docker.io/library/nginx@sha256:<hex>`. With both a tag and a digest, both are kept. Pinned by `image_values` (Task 2) and the fixture.
4. **Upper case by position.**
   - `"Registry.Example.com/app"` is valid.
   - `"ghcr.io/Org/App:1.2"` is a repository error.
   - `"MyOrg/app"` is our strictness error.
   - Upper case in a tag (`"app:V1"`) is valid.

   Pinned by `image_values` and `image_errors` (Task 2).
5. **Digest bytes.** `as_bytes()` equals the decoded hex. `Display` round-trips the literal. A sha512 digest has 64 bytes. Pinned by `digest_accessors` (Task 1).

**Normalization** (from `distribution/reference` v0.6.0 `splitDockerDomain`; the fixture is the authority):
1. Take the digest from the first `@`.
2. The tag is after the last `:` that comes after the last `/`.
3. If there is no `/`, the registry is `docker.io` and the repository is `library/<name>`.
4. Otherwise, the first component is the registry when it is `localhost`, contains `.` or `:`, or has upper case (that last case is our strictness error, see Decisions).
   - `index.docker.io` becomes `docker.io`.
   - Otherwise the registry is `docker.io` and the whole name is the repository.
5. A `docker.io` repository without `/` gets `library/`.
6. `canonical` is `registry/repository`, then `:tag` (or `:latest` when there is neither a tag nor a digest), then `@digest`.

**Grammar:**
- A repository component matches `[a-z0-9]+((\.|_|__|-+)[a-z0-9]+)*`; components are joined by `/`.
- A registry is a domain (components `[A-Za-z0-9]` or `[A-Za-z0-9][A-Za-z0-9-]*[A-Za-z0-9]`, joined by `.`) or a bracketed IPv6 address `\[[0-9A-Fa-f:]+\]`, with an optional `:port` of digits.
- A tag matches `[A-Za-z0-9_][A-Za-z0-9_.-]{0,127}`.
- The repository path is at most 255 characters.
- A name that is exactly 64 lower-case hex digits is rejected.
